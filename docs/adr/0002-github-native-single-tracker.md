# GitHub-native, single tracker — no adapter layer

border-collie targets GitHub Issues + GitHub PRs exclusively, via the `gh` CLI. We deliberately do not abstract over trackers the way `/setup-matt-pocock-skills`, sortie, and Symphony do — because blocking semantics are the least portable part of any tracker, and both tracker-agnostic reference projects ended up *not* gating dispatch on dependencies at all. The dispatchable set is border-collie's reason to exist, and it leans directly on GitHub-specific machinery: native issue dependencies (`blocked_by`), label-as-claim, `ready-for-agent`/`ready-for-human` labels, `Closes #N` auto-close on merge, draft→ready PR transitions, server-computed mergeability, and `gh pr update-branch`.

The hedge: all tracker operations live behind one seam — a single module (dispatchable-set query, claim/release, PR operations) with the `gh` invocations hidden inside — so a future port is "reimplement one module," not "unpick `gh` calls from the loop." No adapter registry, no config switch, no second implementation until a real second tracker demands one.

## Amendment (2026-08-25) — the port stays deferred, not abandoned

Owed by the same reconciliation as [ADR 0009](0009-daemon-execution-substrate-not-github-actions.md): the daemon changes the execution substrate underneath the tracker seam — where a session runs, how it is isolated, how it authenticates — not the seam itself. Nothing about that move forces a second tracker implementation into existence. GitHub Issues and GitHub PRs remain the only tracker border-collie targets, the single module this ADR already isolates the `gh` invocations behind is exactly where a second implementation would go if one were ever needed, and no real second tracker has demanded one yet. Deferred, not abandoned: the port stays a future move worth keeping cheap, not a scope this ADR is walking back.
